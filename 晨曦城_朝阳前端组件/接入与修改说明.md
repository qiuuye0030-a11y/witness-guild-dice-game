# 晨曦城 · 朝阳前端组件

已从原方案拆出可复用的显示层。此目录独立保存，现有完整游戏、骰子系统及分享包均未修改。

## 最快的拼接方法

打开 `可直接拼接_完整片段.html`，复制全部内容，粘贴到目标游戏 HTML 的 `<body>` 内、希望显示界面的位置。片段含 CSS、结构、显示接口和初始化，可离线使用，无网络依赖。

该片段只创建一个新界面，不会自动隐藏游戏旧界面，也不会接管旧按钮和存档。等游戏改好后，再决定旧显示区域的替换位置。不要将片段嵌入现有按钮、段落或表单内。

## 更方便长期修改的方法

1. `01_界面样式.css`：颜色、字体、背景层、按钮和手机布局。颜色在文件开头 `.cx-root` 中修改；阅读框宽度可设置 `--cx-panel-width`。
2. `02_界面结构.html`：放入 body，调整顶栏、正文和底栏位置，不含完整网页外壳。
3. `03_界面接口.js`：在结构之后加载，负责显示与事件。
4. `双击预览.html` + `演示剧情.js`：保留原来渡口到钟鼓楼的演示，可双击浏览。演示剧情不属于正式游戏规则。
5. `原版设计方案_参考.html`：保留原方案和规范便于对照。

分文件接入：CSS 用 `<link rel="stylesheet" href="01_界面样式.css">` 放到 head，复制结构到 body，在结构后用 `<script src="03_界面接口.js"></script>` 加载接口。文件路径按实际位置调整。单文件分享时用合并片段，不需要另外分发 CSS/JS。

分文件与合并片段是两种替代方式，只使用其中一种。修改分文件后，合并片段不会自动更新；重新运行上一级的 `整理朝阳组件.py` 会从原始参考生成整套文件并覆盖输出，保留手动修改时不要运行它。

## 把游戏数据显示到新界面

```js
(function () {
  const root = document.querySelector('[data-cx-root]');
  const ui = ChenxiUI.create(root);
  ui.render({
    phase: 1,                       // 0 初晓 / 1 晨曦 / 2 旭日 / 3 朝晖
    place: '见证者公会',
    time: '第一日 · 清晨',
    speaker: '旁白',
    narrative: '这里放游戏当前剧情。\n可以换行，也可以显示骰子结果。',
    choices: [
      {id:'visit', label:'前往公会'},
      {id:'roll', label:'尝试行动', risk:true, tag:'需要骰子判定'},
      {id:'locked', label:'进入训练场', disabled:true, tag:'需要：完成登记'}
    ],
    menus: {restart:true, journal:true, inventory:true, settings:true}
  });
  root.addEventListener('chenxi:choice', function (event) {
    const actionId = event.detail.id;
    // 在这里调用现有游戏的行动函数，然后用 ui.render 更新结果。
    // 不要在前端组件里重新实现骰子、概率、成长或存档规则。
    console.log('选择行动', actionId);
  });
  root.addEventListener('chenxi:menu', function (event) {
    // restart / journal / inventory / settings，分别接入现有功能。
    console.log('打开菜单', event.detail.action);
  });
})();
```

`render` 只更新传入字段；省略字段保留原样。`choices:[]` 清空选项；菜单配置为 false 隐藏，为 true 显示。`selected:true` 显示已选状态，由游戏自己决定何时显示，不自动推进剧情。`ui.setPhase(2)` 可单独改变时段；`ui.destroy()` 移除组件事件监听，不删除 HTML。

也可在 `ChenxiUI.create(root, {onChoice, onMenu, onClue})` 中传入回调，回调参数为 `(detail, ui)`。同一 root 重复 create 返回原实例，后传入回调不会替换原回调。回调和同名事件都触发，只选一种方式处理业务，避免重复掷骰或重复保存。

## 接入现有完整游戏时的对应关系

目前游戏使用 `campBody` / `.camp-story` 承载主线、`.camp-choice` 显示行动、`.camp-sidebar` 显示角色信息，并有自己的 `dawn-scenery` 天空主题。本组件使用独立的 `cx-` 样式与 `--cx-` 变量，适合在游戏稳定后逐步替换阅读显示区域。

这个组件没有角色属性侧栏、创建角色表单、骰台或战斗面板。那些模块继续由原游戏管理；需要在同一界面展示时，将其放入 `.cx-panel` 内的新增区域或另设侧栏，并补充相应样式。不要只把 `campBody` 的内容复制过来就假定原按钮绑定已迁移。

## 正文与线索

默认 `narrative` 用纯文本写入，玩家输入不会作为 HTML 执行。需要段落或线索格式时可传 `narrativeHTML`，只用于你自己可信的游戏内容，禁止直接填入玩家输入或未清洗的外部文本；同次提供两者时 HTML 优先。

```js
ui.render({narrativeHTML:'你发现了 <button type="button" class="cx-clue" data-clue-id="letter">一封请柬</button>。'});
root.addEventListener('chenxi:clue', e => {
  // e.detail.id / e.detail.text，接入现有行记。
});
```

不使用全局通用样式、不占用原有 DOM id，不含剧情延迟计时器。SVG 城楼已改为直接路径，复制多个组件不会重复引用 SVG id。多个界面应分别取得自己的 root 后 create，避免用一个 querySelector 更新所有实例。仅暴露 `window.ChenxiUI`；若宿主已有同名全局，请统一改名。
