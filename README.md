# 见证者公会 · 互动式骰子文字游戏

当前源码：**v12.05.03（战斗规则V17、成长规则10082、讨伐与魂骨版）**。单人离线养成与斗魂游戏，提供经典深靛、晨曦朝阳两种主题，两主题采用相同规则。

v12.05.03 在 v12.05.02 基础上修：赞助版转正菜单恢复辅助会员（伊其然、伊筱蓓，仍是正确的 2 对 2 阵容）；挑战完成记录按实际主考官 ID 记账并新设独立挑战账本，右上角“成就”与“挑战记录”分开，按转正考核／会员切磋／进阶试炼／高难挑战四类展示、未完成优先，会长雪寂冬与神秘伤疤女归入同一高难目录；手动转正战在玩家无可行动时按原 180 秒裁判口径提前结算；成就弹窗调度不再被后台重绘移除；新增“十万年魂兽图录”；随机初始武魂潜力改为 1—10 档各 10%。

## 仓库布局

本仓库按分享包的目录格式整理，主页面只保留源码、构建输入与一份资料目录：

| 位置 | 内容 |
|---|---|
| `骰子系统/` | 源码（systems、tools、fixtures、output 证据） |
| `晨曦城_朝阳前端组件/` | 晨曦主题的组件与样式输入 |
| `见证者公会战斗试玩.html` | 构建用的基础页面 |
| `资料与校验/参考资料/` | 更新说明、参数对照、成就清单、魂兽库、武魂删留映射与接入指南（即分享包里 `资料与校验/参考资料` 的同名文件） |
| `骰子系统/output/v12/` | 回归测试报告（分享包把它复制到 `资料与校验/测试报告`，仓库内只保留这一份） |
| `docs/` | 仓库自身的待办板与验收记录 |

两个主题 HTML 与分享 ZIP 不作为源码进仓库，通过 Release 附件分发；构建会在仓库根目录生成它们，已被 `.gitignore` 忽略。

## 游玩与构建

发布附件里的两个主题 HTML 全部资源内置，浏览器直接打开即可离线游玩。源码构建在仓库根目录：

```text
npm run build        # python 骰子系统/_build_v12.py，生成两份主题HTML与分享包
```

需要 Node.js 22 与 Python 3.10+，只用标准库，无 npm 依赖。构建会生成 `见证者公会_v12.05.03版_*.html`、`v12.05.03版双前端分享/` 与 `见证者公会_v12.05.03版_双前端分享包.zip`。

## 源码入口

- 战斗、成长、事件、骰子模块：`骰子系统/systems/`；讨伐与魂骨规则：`骰子系统/systems/v12/`；独立讨伐模块包（七只十万年魂兽、友方 NPC、魂骨、188 项校验器）：`骰子系统/systems/v12/modules/`。
- 故事与事件：编辑 `骰子系统/story-source-1003.json`，再运行同目录 `_sync_story_data.py`。
- 武魂精简：`资料与校验/参考资料/武魂删留映射.csv`、`精简武魂总表.csv` 记录删留与档位；`catalog.js` 为生成后的武魂库。
- 冻结对照：`骰子系统/fixtures/`（`1006-reference/`、`1007-reference/`、`1008-before-rollback/`、`v11-before-matrix/`、`v13-baseline/`，以及 `v12.02-reference/`、`v12.04-reference/`），只用于对照，不进入游戏成品。

顶层 `core.js`、`campaign.js`、`campaign-events.js`、`systems/events/legacy-data.js` 与战斗引擎包由 `_build_v12_modules.py`、`_sync_systems.py`、`_sync_v13.py` 生成，不要直接编辑，也不要追加 prototype 覆盖补丁。

## 验证

在仓库根目录：

```text
npm test             # node 骰子系统/tools/verify-v12-package.cjs，核对主题HTML、脚本编译与构建清单
npm run regression   # python 骰子系统/tools/verify-v12-release.py，跑 17 组回归
```

构建必须先于检查：两项检查都读取生成后的主题 HTML 与 `v12.05.03版双前端分享/资料与校验/构建清单.json`。回归覆盖 v12.05.03／v12.05.02／v12.05.01／v12.05／v12.04／v12.04 弹窗／v12.03.01／v12.03／v12.01／v12 核心、界面组件、旧战斗与伤疤女挑战、成长曲线、隐藏成就、培养与读档，以及独立模块包 188 项；逐项记录写入 `骰子系统/output/v12/`。

两处为仓库可移植性所做的最小改动（断言未改）：

- `tools/verify-v1204.cjs` 原本读取同级开发目录 `v12.02开发`／`v12.04开发` 的两个基线，仓库把它们收入 `fixtures/v12.02-reference/dawn.css` 与 `fixtures/v12.04-reference/trait-pool.json` 并指向 fixtures。
- `_build_v12.py` 原本从仓库根目录取资料文档，现改为读 `资料与校验/参考资料/`，与上面的目录整理一致。

界面检查为离线组件与脚本检查，**尚未完成真实浏览器截图验收**；来件战报的新规则重放只是单场功能例证，不作为整体胜率或平衡结论。详见 [v12.05.03 更新说明](资料与校验/参考资料/v12.05.03_更新说明.md)。

GitHub 自动检查按“构建 → 封装核对 → 17 组回归”执行，远端结果以 Actions 为准。
