# 见证者公会 · 互动式骰子文字游戏

当前源码：**v12.05.01（战斗规则V17、成长规则10081、讨伐与魂骨版）**。单人离线养成与斗魂游戏，提供经典深靛、晨曦朝阳两种主题，两主题采用相同规则。

v12 线在 v11 之后分六次修订：v12 加入讨伐战、魂骨装备与精简武魂库；v12.02 接入友方 NPC；v12.03 平衡讨伐血量（团队×2、独行×1.5）并修复测试事件卡顿；v12.03.01／.02 重做霜蚋冰壳与霜域并下调其强度；v12.04 上线万年魂骨 20 条特性、援军与成就弹窗；v12.05 扩库到七只十万年魂兽并调整天赋与掉骨顺序；**v12.05.01** 取消两条特性的输出属性限制（弥天瘴羽增伤不再要求毒属性、焚龙破甲破甲不再限火属性）、正式讨伐事件可选择七只魂兽中的目标，并把魂骨“已吸收／待融合”、属性加持与特性正文改为独立的魂骨说明样式。

## 游玩与构建

发布附件里的两个主题 HTML 全部资源内置，浏览器直接打开即可离线游玩。源码构建在仓库根目录：

```text
npm run build        # python 骰子系统/_build_v12.py，生成两份主题HTML与分享包
```

需要 Node.js 22 与 Python 3.10+，只用标准库，无 npm 依赖。构建会在仓库根目录生成 `见证者公会_v12.05.01版_*.html` 与 `见证者公会_v12.05.01版_双前端分享包.zip`。

## 源码入口

- 战斗、成长、事件、骰子模块：`骰子系统/systems/`；讨伐与魂骨规则：`骰子系统/systems/v12/`；独立讨伐模块包（七只十万年魂兽、友方 NPC、魂骨、188 项校验器）：`骰子系统/systems/v12/modules/`。
- 故事与事件：编辑 `骰子系统/story-source-1003.json`，再运行同目录 `_sync_story_data.py`。
- 武魂精简：`武魂删留映射.csv`、`精简武魂总表.csv` 记录删留与档位；`catalog.js` 为生成后的武魂库。
- 冻结对照：`骰子系统/fixtures/`（`1006-reference/`、`1007-reference/`、`1008-before-rollback/`、`v11-before-matrix/`、`v13-baseline/`，以及本仓库补入的 `v12.02-reference/`、`v12.04-reference/`），只用于对照，不进入游戏成品。

顶层 `core.js`、`campaign.js`、`campaign-events.js`、`systems/events/legacy-data.js` 与战斗引擎包由 `_build_v12_modules.py`、`_sync_systems.py`、`_sync_v13.py` 生成，不要直接编辑，也不要追加 prototype 覆盖补丁。

## 验证

在仓库根目录：

```text
npm test             # node 骰子系统/tools/verify-v12-package.cjs，核对主题HTML、脚本编译与构建清单
npm run regression   # python 骰子系统/tools/verify-v12-release.py，跑 15 组回归
```

构建必须先于检查：两项检查都读取生成后的主题 HTML 与 `v12.05.01版双前端分享/构建清单.json`。回归覆盖 v12.05.01／v12.05／v12.04／v12.04 弹窗／v12.03.01／v12.03／v12.01／v12 核心、界面组件、旧战斗与伤疤女挑战、成长曲线、隐藏成就、培养与读档，以及独立模块包 188 项；逐项记录写入 `骰子系统/output/v12/`。

`verify-v1204.cjs` 原本读取同级开发目录 `v12.02开发`／`v12.04开发` 的两个基线文件；本仓库把它们作为 `fixtures/v12.02-reference/dawn.css` 与 `fixtures/v12.04-reference/trait-pool.json` 收入，并把该脚本的两处路径指向 fixtures（断言未改动）。

界面检查为离线组件与脚本检查，**尚未完成真实浏览器截图验收**；来件战报的新规则重放只是单场功能例证，不作为整体胜率或平衡结论。详见 [v12.05.01 更新说明](v12.05.01_更新说明.md)。

GitHub 自动检查按“构建 → 封装核对 → 15 组回归”执行，远端结果以 Actions 为准。
