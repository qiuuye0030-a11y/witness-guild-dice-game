# V14 战斗系统优化：跨电脑交接与检验任务书

日期：2026-10-15。交接对象为另一台电脑上的开发与检验人员。

**已定稿基线为游戏10.05、战斗V13；本任务的候选战斗规则命名为V14。** V14不是已经发布的游戏版本号。本次交付任务书、可运行基线、检查脚本与现有证据；尚未实现V14，也未求得各考官的最优AI。不得把下文候选数值当成已验证结果。按用户要求，本次不上传GitHub。

## 1. 用户确认的目标

1. 逐一检查14位会员考官的AI交战逻辑，在可行范围内寻找各自综合胜率最高的独立策略。
2. 胜率超出50%±15%，或出现额外大幅浮动时，提交原因和调整方案。
3. 引入统一异常状态系统，先选少数描述有依据的会员试行，再决定是否扩大。
4. 增加敏攻系专属攻击魂技：以敏捷参与伤害计算，降低本次伤害，换取下次行动条加快。
5. 增加多段小额攻击魂技；考虑防御结算后，可给予更高总体倍率，但必须用模拟验证。
6. 重点检验减益偏弱，提出并对照测试优化方案。

沿用的约束：考官54→51等不掉环降级、90%攻击、双方0.3秒回气；严格按实际环数开放技能，最多六技；正向永久六维成长三倍；减益持续整场；受控不能闪避；v12延续的魂力消耗及同时受击防护机制。保留V13已去除的通用效果上限，不用恢复旧上限代替平衡分析。

文本和魂技描述修改参考用户指定的 `D:/novel/novel-scene-craft/SKILL.md`。该技能不自动存在于另一台电脑；交接包附其快照及改稿参考。原人设事实、触发条件、原有伤害属性优先，候选新增异常必须标注为游戏试行设定。

## 2. 如何在另一台电脑开始

解压交接包到任意路径，保留目录结构。先读本任务书、V13规则、10.05交接文档和 `文件校验清单.json`。不要依赖原电脑的D盘路径。

直接打开两个10.05 HTML可离线试玩。数值检查需已安装Node.js；构建另需Python3。基础模拟只用Node内置模块，不要求联网安装依赖。在解压目录的“骰子系统”中依次执行：

```text
node verify-1005.cjs
node verify-members-1005.cjs
node verify-quests-1005.cjs
node audit-v14-baseline.cjs
```

完整重跑基线：`node simulate-1005.cjs`，随后再次运行审计脚本。报告写入本目录output。原始JSON已附包中，可以先复核现有结果再重跑。

浏览器检查脚本 `verify-ui-1005.cjs` 使用Playwright和Edge，原电脑的浏览器路径及NODE_PATH不能照搬；先配置本机依赖与浏览器路径。无法运行自动浏览器时，手工检查双主题、手机布局、保存恢复、考核预览与实战技能数，并记录未执行项，不能标成通过。

修改应建立新的V14模块与测试入口，保留V13可切换运行。当前V13构建为 `_sync_v13.py` 后 `_build_1005.py`；它们会重建10.05，不应拿来直接发布V14。一次性迁移脚本不在本包中提供执行入口。新建V14构建、独立规则版本和快照迁移，不覆盖定稿V13。

针对当前越界样本，先提交以下可检验调整方案：

- **伊筱蓓13.3%**：先将纯辅助单挑从综合主表拆出，补测固定输出友军的2v2；比较优先保护/恢复主输出、先控制敌方关键施法者、按缺口施盾三种AI。若2v2仍低于35%，分别试治疗/盾费用降低10%或相关读条降低10%，逐项测，不直接增加攻击倍率改变人设。
- **夏维宇33.3%**：先记录血锢合法窗口出现率、抓取率、标记覆盖和血夜首击兑现率；对比“先低费攻击标记→敌方读条时血锢”的条件策略，六环才加入血夜排序。若抓取率正常但胜率仍低，分别测试血噬费用降低10%或基础攻击技倍率增加5%，检查拖蓝是否反而过强。
- **李一行63.3%、伊其然36.7%**：先扩样本，不因接近边界直接调数值；若李一行确认超65%，分解霸气消费和伤害来源，再试主力爆发倍率降低5%或费用增加10%；若伊其然2v2仍低于35%，优先修护甲覆盖和保护目标，再单测护甲费用降低10%。

这些是下一阶段候选，不是已验证有效的补丁。所有增减均应相对V13原值计算，并记录回退点。

不要将50%±15%误认为要求每种极端玩家都与每位考官五五开。综合结果需要固定、公开的玩家构成权重；每个流派和环数分别报告。原有强弱克制可以保留，异常必须解释。

当前代码已发现的待验证点：

- `combat-v13-extension.js` 对多项六维减益的AI评分额外乘0.65，再乘精神判定成功率，尚未按剩余战斗时间估计整场收益；这是可能低估减益的线索，不是已经证实的唯一原因。
- 多项效果AI按固定六维权重估分，与直接攻击的伤害评分是否同量纲需核对；单看技能倍率不能解释“AI不用”。
- 同源六维状态按source更新；普通slow等读取最大值，覆盖收益可能很小；UI文字未必准确区分行动条减速和读条减速。目前slow同时影响两者。
- D主要影响常规防御，A影响行动率及命中/闪避，C影响减耗/读条；只减S未必会让已有最大MP或当前MP同步下降。要核实各六维的实际受益路径，避免“描述减魂力、资源却完全不动”。
- 当前防御核心为 `raw×100/(100+标准化防御)`，是比例减伤。同一防御下将总伤害均分多段，理论总值基本不变，差别主要在逐段取整、命中、护盾和受击触发。不能按固定减伤模型推导多段补偿。
- 清凌目前对早期泯灭分身及低血换位有固定判断；其余技能主要依赖通用评分和若干专用修正。存在专属判断不等于已做过全局最优搜索。

## 4. 统一实验设计和异常判据

### 4.1 三组实验分开

**A：AI优化。** 数值与V13完全相同，只换策略。以V13当前AI为对照，公平地选择“在给定对手集合上的最好候选”。不得一边改伤害一边声称AI提高胜率。

**B：数值平衡。** 固定AI后，分别比较异常状态、新技能、减益方案；每次只改变一组变量，最后做整合测试。

**C：正式考核体验。** 用正式成长人物、考核难度、标准难度、1v1、2v2分别测试，不能把标准切磋和带辅助考核混成一张胜率表。

### 4.2 对手与样本

覆盖六类流派、低中高潜力、四/五/六环及以上、生命与精神伤害、高防御、闪避拖蓝和控制连段。核心平衡池固定玩家权重，建议先按六流派等权；另列按实际玩家分布加权的体验池。两者结论分开。

玩家策略至少含：V13自动、直接爆发、先强化、先减益、敏攻闪避拖蓝、针对考官机制的脚本。纯闪避是压力测试，不能成为全部评估样本。AI不能读取未揭晓骰点、未来随机数或敌方隐藏选择；可读取战场已公开的读条与状态。

用相同人物、相同初始局面与种子清单配对比较；随机调用顺序变化会破坏逐骰对应，应说明随机流设计，不能只凭同种子宣称完全消除了运气。训练、验证、最终保留测试集按人物种子拆分，禁止同一人物改个战斗种子同时进入训练与测试。

搜索初筛可每候选200—500场；最终每位考官每个主要模式至少1000场，另分至少5批不同种子。报告Wilson95%区间、样本数、胜/负/平、平均与分位战斗时长、魂力耗尽率、无效行动率、各技能施放/命中/抵抗次数、控制覆盖和伤害构成。辅助考官以2v2主表、单挑诊断附表呈现。

### 4.3 异常定义

- 综合考官胜率点估计低于35%或高于65%：必须给出原因和调整候选；置信区间跨边界时标注证据不足，并补样本。
- 分批同口径胜率最大差大于15个百分点，或相对V13配对胜率变动超过10个百分点：作为“浮动大”的交接默认触发线，需复跑并判断抽样、角色池或机制波动。这两条数值为本任务书建议的可执行口径，可在正式测试前修订并固定。
- 全样本落在范围内但某主要模式/流派超过界限，同样列分组异常，不用平均数遮蔽。
- 100%连控、近乎无代价的无限加速、异常高超时/平局、2v2单点秒杀等机制问题不受胜率范围豁免。

异常报告模板：考官/模式与池权重 → V13/候选胜率及区间 → 分组差异 → 最少三份可复现战报 → 原因证据 → AI调整 → 仍异常时的单变量数值方案 → 复测结果与副作用。低胜率先修无效AI，高胜率先查漏洞；不要求靠削弱AI来抵消机制缺陷。

## 6. 异常状态系统：少数会员试行

现有statuses、dots、control已经存在。本项是统一机制与显示，不另造一套绕过免控和存档的系统。第一批建议三人：秦衍试行感电/麻痹，雪寂冬试行寒滞，林洛樱试行毒蚀。暗牧待第一批稳定后第二批扩展，避免同时重做全部毒素组合。

候选映射与初值：

|会员与技能|异常试行|首轮参数建议|避免重复收益|
|---|---|---|---|
|秦衍·雷光|感电：行动条减速|10%，2秒，单层刷新|替代原slow；原描述仅写读条减速，行动条效果属新增试验，必须同步修订描述|
|雪寂冬·寒影奔袭/冻气龙卷|寒滞：行动与读条分别减速|两者各15%，沿用各技能现有时长|替代原slow；原短眩晕仍走control和4秒免控，不凭寒滞再叠一次眩晕|
|林洛樱·桃毒蚀脉|毒蚀：魂力强度/操纵削弱|沿用S－16%、C－12%，整场，同源刷新|统一承载和UI，不额外再加原效果之外的毒伤、削防或其他减益|

统一记录：状态id、名称、施加者、技能来源、作用对象、施加时间、到期/整场标记、强度、层数/叠加规则、抗性判定结果、驱散标签与规则版本。当前不新加玩家驱散魂技，仅预留字段。

明确约定：硬控制统一control并遵守免控；软减速不视为硬控。来自减益类别的异常继续遵守整场有效；攻击附带状态可按原时长结束，不能把攻击类的短减速悄悄改成整场。相同来源刷新；同类不同来源采用现行最大值作第一轮对照，不默认相加；毒伤独立来源沿用原dots规则。更强被更弱覆盖、施加失败却出现UI标记、死亡后重复触发都须测试。

界面显示异常名、数值、剩余秒数/“本场”、来源；日志区分命中、抵抗、刷新、结束。保存恢复须保留剩余时间、层数与来源；回放、AI估值、实际结算使用同一规则函数。

## 7. 敏攻专属攻击：以敏捷换取后续出手速度

候选名称“掠影追击”（临时机制名，正式生成仍结合武魂命名）。仅敏攻生成池可抽到，分类仍为攻击，不新增猎魂大类；新存档生成规则需单独版本标记。

以有效敏捷A为主要伤害参数。先以同阶段、同潜力、相同费用/读条的普通攻击魂技作参照，选系数使参照人物单次伤害为对照的80%—90%，再比较3次以上行动内的总收益。A与PA并非同单位，不能直接把PA替换为A后仍沿用原倍率。建议从 `raw＝1.2Q×kA×伤害折扣` 起试，k由基准人物PA/A校准，测试时固定，不逐局回调抵消敏捷成长。

命中后赋予施法者“追势”：下一次行动条填充速率×1.20，消耗一次后结束，最长持续8秒；不加快读条或0.3秒回气，不立即赠送行动。未命中不获得。多目标、多段也每次施放最多赋予一次；同源刷新不叠层。以上20%、8秒与折扣均为待测试初值。

追势从本次攻击完成后、下一次行动条开始填充时生效；被控制期间不增长，但时长照常流逝，不能消除控制或触发免费出手。不得把受控时的主动闪避重新放开。AI估值计入实际缩短的等待、下一次可用技能与费用，不把未来收益直接当本次斩杀伤害。

专项矩阵：A低/中/高，对高防/高敏/控制；命中/未命中、普通/精神通道限制、同刻控制、保存恢复、重复施放、180秒终局。先决定生成权重是否从现有攻击子类中分流，不降低其他大类权重。

## 8. 多段小额攻击

候选名称“连刃”（临时机制名），分类攻击。第一轮3段，总原始倍率先对照单段的1.00、1.10、1.20、1.30倍，费用和读条先固定。记录每段与总伤害、穿盾、魂力保护支出及命中结果后，再选倍率。

推荐首轮同一次施法、同一目标、共用一次命中判定，命中后逐段扣伤。每段按当时防御、盾、护持结算；单次施法的施法费、附带控制/吸血/感电、首击强化等默认只触发一次。逐段暴击等当前未有规则不临时添加。若想每段独立命中，应列为另一候选，单独说明方差及异常触发预算。

复用V13同刻受击的魂力保护预算，不能每段重置保护额度、重复触发一次性免伤或每段重复缴纳整次魂技费用。魂力耗尽、护盾被击碎、目标中途死亡后剩余段如何处理必须固定；建议死亡后终止余段，不转移目标。

必须检查：比例减伤下是否真的需要补偿；每段最低1伤导致低倍率攻击获利；取整误差；防御/冰甲/格挡/闪避/首击/流血标记的触发次数。高防目标上测出的补偿不能导致低防目标过度爆发。若无机制性损失，允许最终只取1.00倍，不能为满足预想而强加高倍率。

## 9. 减益偏弱：先定位，再调整

### 9.1 分开判定三个原因

**效果没生效**：六维变化→派生攻击/防御/行动/费用/读条是否即时变化；整场状态是否意外过期；多项是否只应用首项；命中判定与抵抗日志是否一致；S/P变化是否应影响资源上限要单独定规则，不能默认为已有功能。

**生效但AI不用**：记录可用时是否选择、预估收益、实际后续收益、已存在同源状态和抵抗重试次数；比较强制开局减益脚本与现有AI。

**AI使用但经济性差**：计算一次行动、读条、魂力的机会成本；短战斗来不及回本、削错维度、已有高额削弱使新增收益接近零，都可能导致弱。

### 9.2 候选按顺序隔离测试

|方案|只改的变量|预期与检查|
|---|---|---|
|D0|不改，V13对照|记录实际减益次数、命中及持续收益|
|D1|AI移除固定0.65折，改按剩余时间与敌输出估算|优先判断是否仅估值偏低；不得修改判定概率和效果值|
|D2|生成六维的优先级/目标选择|输出优先削B/S/P，高敏优先A，护甲优先D，耗能读条构筑优先C；保留其他六维随机可能|
|D3|减益施法费×0.85，或读条×0.85，分别实验|降低前置成本；读条保留现有合法下限，两个折扣不得一开始一起给|
|D4|单项幅度或双/三项折算小步增加10%—15%|仅在D1—D3仍不足后测试；检查跨来源接近100%削弱的锁死|
|D5|攻击附带小幅减益的混合技|留到最后；与攻击异常试行重叠，按总预算削减伤害，不直接白送整场高额削弱|

不要给减益再上一层相同精神抵抗，也不要把所有减益改必中。候选可比较“首轮失败的部分费用返还”，但需单列，不默认实施。保留整场有效和属性最低零；区分主动减益技能与攻击附带短状态。

若出现削减叠到零、行动率常驻最低而对方无反制等情形，提出同来源规则、作用维度和成本方案，并单独提交必要的递减收益候选；不擅自恢复V13已移除的统一65%等上限。

## 10. 实施顺序、交付和验收

1. 冻结并复跑V13，校验文件、种子与统计口径；记录本机运行环境。
2. 加入决策日志，逐会员审计；先完成AI优化A组，输出14份策略卡及独立保留集结果。
3. 按异常触发线提交胜率异常表与调整候选；辅助另测2v2。
4. 独立实现状态系统三人试行，完成触发/抵抗/显示/存档测试。
5. 独立加入敏攻追势与三段攻击测试开关，验证伤害和行动经济。
6. 完成减益D0—D4对照，再做V14整合；保留每项开关方便定位影响。
7. 新建V14引擎/前端/存档标记及构建入口；双主题必须嵌入同一引擎。新快照不能冒充V13，旧战斗无法兼容时回登记并保留已用次数、战报、战胜档案。

接手方应交付：V14候选规则、每会员AI参数与选型依据、可重跑种子与人物池、胜率表与置信区间、全部异常的调整建议、状态与两类新技能专项报告、减益对照报告、代表性回放、双主题离线文件及迁移记录。

验收要求：现有专项与事件回归不退化；四/五/六环技能数正确；资源合法且无无限循环；180秒结算正确；状态可见且存读档一致；敏攻提速只作用下一次行动条；多段费用/防护/附带触发次数正确；AI不重复无效减益、不读未来随机；35%—65%之外及额外大幅波动均有证据和方案。尚未修复项必须明列，不能用“总体平均正常”收尾。
